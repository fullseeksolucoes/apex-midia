Flash session · 60s

Vertical videos: unpillarboxed + one-tap fullscreen

Portrait videos were squeezed into a landscape box (tiny, black bars) and fullscreen was buried in the provider's menu. Now they show large and correctly proportioned, with an app-level fullscreen that works on every provider.

Before

9:16 video pillarboxed in a 16:9 box; YouTube fullscreen impossible, Vimeo FS hidden in the ··· overflow.

After

Correct 9:16 sizing (capped 70vh) + an Expand button opening a large centered lightbox with real fullscreen.
The root cause (the surprising part)

The data was wrong, not just the CSS

  • Every video row was stored 1920×1080 / "wide" — even portrait ones. The client added them with the admin's default "Horizontal" toggle. The player sizes purely from width/height, so vertical content pillarboxed.
  • Decision: auto-correct aspect from Vimeo oEmbed (the same call already used for posters returns the true dimensions → e.g. 240×426 = 9:16). Reject trusting the admin toggle alone (it's the thing that was wrong).
  • YouTube/Panda/file keep the toggle — YouTube's oEmbed reports the default 16:9 player, not the true Shorts aspect, so it's untrusted.
What changed

Data fix + fullscreen UX

  • lib/video-thumbnail.ts — resolveVideoMedia returns true {width,height,aspect} from oEmbed (null-safe, 4s timeout).
  • server/routers/portfolio.ts — save-time resolver applies corrected dims on create/update.
  • server/routers/media.ts — backfillVideoAspect mutation (dry-run first) corrects existing rows + revalidates.
  • components/media/VideoLightbox.tsx (new) + VideoPlayer.tsx — expand button → modal with clean embed, allowFullScreen for all providers, contain-fit up to 90vw×90vh.
  • lib/video-providers.ts — lightboxUrl (clean embed keeping controls + fullscreen).
How it was verified

Adversarial review + green gate

  • reviewer: approve Tried 8 refutations — all held: oEmbed failure falls back to stored dims (no data loss), images untouched, dry-run writes nothing, YouTube fullscreen now works in the lightbox, no listener/scroll-lock leak, z-[60] above navbar.
  • Gate green — tsc clean, eslint clean on all 6 files, next build 31/31 pages.
  • Diagnosed live — on /portfolio/emelys, all 4 videos stored 1920×1080 but Vimeo oEmbed returns 240×426 (vertical), confirmed pillarbox on-screen.
Release / watch-out

One operational step

Merging alone changes zero pixels for existing videos. The render trusts stored dims, so media.backfillVideoAspect({dryRun:false}) must run once post-deploy (dry-run first) to correct the ~7 existing rows. New/edited videos self-correct on save.
  • Static pages update after the backfill's revalidatePath fires.
  • oEmbed overrides Vimeo dims (ground truth) but never on failure — no way to corrupt a correct row.
